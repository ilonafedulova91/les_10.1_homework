# Banking Operations Widget
## Описание проекта
Проект представляет собой бэкенд‑часть виджета для личного кабинета клиента банка. Виджет отображает несколько последних *успешных банковских операций* клиента.
В рамках проекта реализованы функции для:
- маскировки номеров банковских карт и счетов
- форматирования дат
- фильтрации и сортировки операций
Проект развивается пошагово в рамках домашних заданий курса.
## Цель проекта
Подготовка и обработка банковских данных для безопасного и удобного отображения в пользовательском интерфейсе:
- защита чувствительных данных (карты, счета)
- удобная работа с датами
- фильтрация и сортировка операций

## Установка и настройка
### 1. Клонирование репозитория
git clone <URL_репозитория>
### 2. Установка зависимостей
Проект использует `Poetry` для управления зависимостями.
Требования
- Python 3.10 или выше
- Poetry 1.5 или выше
*Установка зависимостей проекта*
В корне проекта выполните команду:
`poetry install`
Эта команда:
- создаст виртуальное окружение
- установит все зависимости из файлов pyproject.toml и poetry.lock
Для установки дополнительных инструментов выполнитe:
`poetry install --with lint`
В группу lint входят:
- `flake8` — проверка стиля
- `black` — форматирование
- `isort` — сортировка импортов
- `mypy` — проверка типов

Запуск:

`poetry run flake8 src`

`poetry run black src`

`poetry run isort src`

`poetry run mypy src`
## Реализованные модули и функции
> `main.py`

Основной модуль программы (`main.py`)
Файл `main.py` является точкой входа в приложение и реализует консольный интерфейс для работы с банковскими транзакциями.
#### Возможности
Программа позволяет пользователю:
- Загружать данные из разных форматов:
    - JSON
    - CSV
    - XLSX
- Фильтровать транзакции:
    - по статусу (EXECUTED, CANCELED, PENDING)
    - по валюте (например, только RUB)
    - по ключевому слову в описании
- Сортировать операции по дате:
    - по возрастанию
    - по убыванию
- Просматривать итоговый список транзакций с форматированным выводом

Обработка ошибок:
- Проверка корректности ввода пользователя
- Повтор запроса при неверных данных
- Обработка пустых результатов

> Пример сценария использования:
>> 1. Пользователь выбирает CSV-файл
>> 2. Указывает статус EXECUTED
>> 3. Включает сортировку по дате (по убыванию)
>> 4. Оставляет только RUB-транзакции
>> 5. Фильтрует по слову "перевод"

Получает отфильтрованный и отсортированный список операций

Связанные модули. `main.py` использует:
* `utils` — загрузка JSON
* `data_loader` — работа с CSV/XLSX
* `processing` — фильтрация и сортировка
* `generators` — фильтрация по валюте
* `process_bank` — поиск по описанию
* `widget` — форматирование вывода
### masks
`get_mask_card_number(card_number: str) -> str`
Маскирует номер банковской карты.
Пример:
```
get_mask_card_number("7000792289606361")
7000 79** **** 6361
```
`get_mask_account(account_number: str) -> str`
Маскирует номер банковского счета.
Пример:
```
get_mask_account("73654108430135874305")
**4305
```
### widget
`mask_account_card(data: str) -> str`
Определяет тип данных (карта или счёт) и возвращает замаскированный номер.
Примеры:
```
mask_account_card("Visa Platinum 7000792289606361")
Visa Platinum 7000 79** **** 6361
mask_account_card("Счет 73654108430135874305")
Счет **4305
```
`get_date(date_str: str) -> str`
Преобразует дату из ISO‑формата в формат ДД.ММ.ГГГГ.
Пример:
```
get_date("2024-03-11T02:26:18.671407")
11.03.2024
```
### processing
`filter_by_state(data: list[dict], state: str = 'EXECUTED') -> list[dict]`
Фильтрует операции по статусу.
Пример:
```
filter_by_state(operations)
filter_by_state(operations, 'CANCELED')
```
`sort_by_date(data: list[dict], reverse: bool = True) -> list[dict]`
Сортирует операции по дате.
Пример:
```
sort_by_date(operations)
sort_by_date(operations, reverse=False)
```
### generators
Модуль содержит генераторы для обработки банковских операций и тестовых данных.
`filter_by_currency(transactions: list[dict], currency: str)`
Фильтрует транзакции по заданной валюте и возвращает генератор операций.
Функция:
- возвращает только операции с указанным кодом валюты;
- выбрасывает `ValueError`, если список пуст или код валюты отсутствует;
- выбрасывает `TypeError`, если код валюты содержит только цифры.
Пример:
```
list(filter_by_currency(transactions, "USD"))
```
`transaction_descriptions(transactions: list[dict])`
Генератор, возвращающий описания транзакций.
Функция:
- возвращает строку `description` для каждой транзакции;
- выбрасывает `ValueError`, если список пуст, транзакция пустая или описание отсутствует.
Пример:
```
list(transaction_descriptions(transactions))
```
`card_number_generator(start: int, end: int)`
Генерирует номера банковских карт в формате `XXXX XXXX XXXX XXXX`.
Функция:
- форматирует числа до 16-значного номера карты;
- выбрасывает `ValueError`, если диапазон некорректный или выходит за допустимые границы.
Пример:
```
list(card_number_generator(1, 3))
```
Результат:
```
0000 0000 0000 0001
0000 0000 0000 0002
0000 0000 0000 0003
```
### decorators.py
Модуль `decorators.py` содержит реализацию декоратора `log`, предназначенного для автоматического логирования выполнения функций.
Декоратор `log` позволяет:
- логировать успешное выполнение функции
- логировать возникшие исключения
- фиксировать входные параметры при ошибке
- записывать логи в файл или в консоль
### utils.py
Модуль `utils.py` содержит функцию load_json_operations, предназначенную для загрузки финансовых операций из JSON-файла.
Функция принимает путь к файлу и выполняет следующие действия:
- Открывает JSON-файл в режиме чтения
- Загружает данные с помощью `json.load()`
- Проверяет, что данные имеют тип `list`
- Если данные являются списком словарей — возвращает их
- Если данные имеют другой тип — возвращает пустой список
- В случае ошибок (`FileNotFoundError` или `json.JSONDecodeError`) функция также возвращает пустой список
Это позволяет безопасно работать с данными и избежать падения программы при отсутствии файла или некорректном JSON.
### external_api
Функция `convert_transaction` предназначена для получения суммы транзакции в рублях.
Функция принимает словарь с данными транзакции и выполняет следующие действия:
- Проверяет, что транзакция не является пустой.
- Извлекает сумму операции (`amount`).
- Определяет валюту операции (`currency code`).
- Если валюта — `RUB`, возвращает исходную сумму.
- Если валюта отличается от `RUB`, выполняется запрос к внешнему API для получения курса валют.
- Полученная сумма конвертируется в рубли и возвращается в виде числа типа `float`.
Для работы с API используется библиотека `requests`.
Ключ доступа к API хранится в переменных окружения и загружается из файла `.env`.
### data_loader
`read_csv(file_path: str) -> list[dict]` cчитывает данные из CSV-файла и возвращает список словарей, где каждый словарь — отдельная транзакция.

`read_excel(file_path: str) -> list[dict]` cчитывает данные из XLSX-файла и возвращает список словарей, где каждый словарь — отдельная транзакция.

Особенности:
- Проверяет, что путь является строкой 
- Проверяет расширение файла (.csv // .xlsx)
- В случае отсутствия файла возвращает пустой список
### process_bank
Функция `process_bank_search` позволяет фильтровать транзакции по ключевому слову (или регулярному выражению) в описании.
Особенности:
- Регистронезависимый поиск (`re.IGNORECASE`)
- Поддержка регулярных выражений
- Если строка поиска пустая — возвращаются все транзакции
Функция `process_bank` считает количество операций по заданным категориям.
Особенности:
- Сравнение без учета регистра
- Возвращает словарь вида {категория: количество}
- Работает даже при пустом списке данных или категорий

## Тестирование
В проекте реализовано модульное тестирование с использованием библиотеки **pytest**.  
Все тесты расположены в директории `tests/` и покрывают ключевую функциональность проекта.
### Структура тестов
#### `test_masks.py`
Проверяется корректность маскирования номеров карт и счетов:
- `get_mask_card_number`:
  - корректное маскирование номеров карт;
  - поддержка строк с пробелами;
  - обработка некорректных значений (пустая строка, ноль, неверная длина).
- `get_mask_account`:
  - корректное маскирование номеров счетов;
  - обработка строковых и числовых значений;
  - выброс `ValueError` при некорректных данных.
Используется параметризация тестов для проверки разных входных данных.
#### `test_widget.py`
Тестируются функции форматирования данных для отображения:
- `mask_account_card`:
  - корректное определение типа (карта / счёт);
  - маскирование номеров с сохранением названия карты или счёта;
  - обработка ошибок типов и некорректных входных данных.
- `get_date`:
  - преобразование даты из формата ISO (`YYYY-MM-DDTHH:MM:SS`) в формат `DD.MM.YYYY`;
  - обработка пустых строк и некорректных форматов дат.
#### `test_processing.py`
Проверяется логика обработки списков операций:
- `filter_by_state`:
  - фильтрация по статусу (`EXECUTED`, `CANCELED`);
  - работа при отсутствии совпадений;
  - обработка ошибок при некорректных входных данных.
- `sort_by_date`:
  - сортировка по дате по убыванию и возрастанию;
  - корректная работа при одинаковых датах;
  - проверка ошибок при пустом списке и некорректных значениях дат.
#### `test_generators.py`
Проверяется работа генераторов:
- `filter_by_currency` — фильтрация операций по валюте и обработка ошибок;
- `transaction_descriptions` — корректность извлечения описаний транзакций;
- `card_number_generator` — генерация номеров карт и проверка диапазонов.
Для подготовки тестовых данных используются фикстуры `pytest`.
#### `test_decorators.py`
Тесты проверяют:
- успешное выполнение функции с выводом в консоль
- обработку исключений с выводом в консоль
- запись логов в файл при успешном выполнении
- запись логов в файл при возникновении ошибки
- проброс исключения после логирования
#### `test_utils.py`
Тесты проверяют:
- корректную работу функции при наличии валидного JSON-файла
- поведение функции при пустом JSON-файле
Для имитации работы файлов и API используется модуль `unittest.mock`.
#### `test_external_api.py`
Тесты проверяют:
- случай, когда валюта операции — рубли (RUB)
- корректную работу функции при конвертации валюты через API
#### `test_data_loader.py`
Тесты покрывают:
- корректное чтение файлов
- обработку ошибки FileNotFoundError
- проверку некорректного типа аргумента
- проверку неверного расширения файла
#### `test_process_bank.py`
Для нового функционала добавлены тесты:
- Проверка поиска:
    - совпадение
    - регистронезависимость
    - отсутствие результатов
    - пустая строка поиска
- Проверка подсчета категорий:
    - корректный подсчет
    - пустые данные
    - пустые категории
    - регистронезависимость
